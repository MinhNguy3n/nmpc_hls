🛠️ WHEN FPGA HARDWARE IS AVAILABLE
═══════════════════════════════════════════════════════════════════════════

1. Program FPGA bitstream with PSO FSM IP core

2. Load UIO driver:
   $ sudo modprobe uio_pdrv_genirq

3. Verify UIO device:
   $ ls /sys/class/uio/
   $ cat /sys/class/uio/uio0/name  # Should contain "pso_fsm"

4. Run full test suite:
   $ ./build/bin/test_xpso_fsm

   This will now execute ALL 7 tests with full hardware validation!


❓ TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

Q: Build fails - "xpso_fsm.h not found"
A: Ensure you're in the correct directory:
   cd .../pso_fsm_v1_0/src

Q: Test says device initialization failed
A: Normal! This means FPGA hardware isn't available. The test will proceed
   with software-only validation. Use this to validate code locally.

Q: How do I know if test succeeded?
A: Look for the line at the end:
   "All available tests completed successfully!"

Q: Can I use this on embedded Linux?
A: Yes! The test is designed for embedded systems. Just compile with gcc
   and run. No external dependencies required.
